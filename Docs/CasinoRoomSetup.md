# 방 제목·비밀번호 UI

`CasinoRoomDialogWidget`은 C++에서 기본 위젯을 구성하는 로컬 팝업이다. 기존 메인 메뉴의 방 만들기 버튼과 검색 결과의 참가 버튼은 에디터 마이그레이션으로 이 팝업에 연결한다. 별도로 BP 노드를 수동 추가할 필요는 없다.

## 사용 흐름

- 방 만들기: 제목을 입력하고, 필요하면 비밀번호를 넣은 뒤 **만들기**를 누른다. 제목 앞뒤 공백은 제거하며 1~48자로 제한한다. 비밀번호는 선택 사항이고 최대 64자다. 비밀번호 앞뒤 공백은 실제 값의 일부이므로 제거하지 않는다.
- 방 참가: 비밀번호가 있는 방의 **참가**를 누르면 방 이름과 마스킹된 비밀번호 입력창이 표시된다. 비밀번호가 없는 방은 별도 팝업 없이 바로 참가를 요청한다.
- **Enter**로 제출하고 **Escape** 또는 **취소**로 닫는다. 요청 처리 중에는 중복 제출과 취소를 막고 처리 중 문구를 표시한다. 빈 배경을 눌러도 닫히거나 뒤의 메뉴 버튼을 누르지 않는다.
- 오류는 팝업의 `ErrorText`에 표시한다. 참가 거부 후 메인 메뉴가 다시 만들어져도 `RestoreMainMenuError`가 기존 `StatusText`에 남은 오류를 복구한다.

참가 대상은 검색 배열의 위치 대신 팝업을 열 때 받은 `SessionId`로 지정한다. 다른 검색 결과가 같은 배열 번호를 차지하더라도 다른 방에 참가하지 않는다. 팝업이 닫히면 비밀번호 입력을 비우고 온라인 이벤트 바인딩을 해제한다.

## UI 디자인 변경

현재 기본 UI는 네이티브 클래스에서 바로 생성된다. 나중에 `CasinoRoomDialogWidget`을 부모로 하는 WidgetBlueprint를 만들고 Show 함수의 `DialogClass`에 지정하면 외형을 바꿀 수 있다.

필수 컨트롤 이름·타입은 `RoomNameInput`/`PasswordInput` = EditableTextBox, `ErrorText` = TextBlock, `SubmitButton`/`CancelButton` = Button이다. 선택 컨트롤은 TextBlock 타입의 `TitleText`, `BodyText`, `RoomNameLabel`, `PasswordLabel`, `SubmitCaption`이다. 필수 컨트롤이 누락되면 실행 중 기본 레이아웃을 사용한다. 이 이름들을 유지하면 C++가 생성/참가 상태, 입력 마스킹, 오류, 버튼 이벤트를 연결한다.

별도 ErrorText를 유지하고 공유 메인 메뉴 `StatusText`를 팝업 안으로 옮기지 않는다. 팝업은 전체 화면에서 입력을 받아 뒤 메뉴를 차단해야 한다. 만들기/참가 버튼의 서버 기능을 BP에 다시 중복 연결하지 않는다.

## 확인할 항목

1. 빈 제목과 49자 이상의 제목을 거부하고, 정상 제목이 검색 목록에 표시되는지 확인한다.
2. 비밀번호 없는 방 참가, 올바른 비밀번호 참가, 잘못된 비밀번호 거부를 서로 다른 PC에서 확인한다.
3. 검색 목록 갱신 후 이전 행의 팝업을 제출했을 때 잘못된 방으로 참가하지 않는지 확인한다.
4. Enter·Escape·취소·배경 클릭과 중복 제출 방지, 취소 후 원래 메뉴 포커스 복구를 확인한다.
5. 이미 시작했거나 꽉 찬 방의 참가 거부, 클라이언트가 거부된 뒤 메인 메뉴에서 오류를 확인한다.
6. 16:9·4:3·넓은 화면에서 팝업과 긴 오류 문구가 잘리지 않는지 확인한다.

디자인 미리보기는 실제 팝업을 디자인 모드로 생성하므로 온라인 요청을 보내지 않는다. EOS 로그인·방 생성·비밀번호 검증은 실제 멀티플레이 테스트로 별도 확인한다.
